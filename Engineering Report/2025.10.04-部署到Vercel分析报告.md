# React+Vite 项目部署到 Vercel 技术分析报告

作者：CodeBuddy 和 刘宇航  
日期：2025-10-04

## 背景
项目为 React+Vite 构建的前端知识库，计划通过 Vercel 连接 GitHub 部署为静态站点。需验证客户端路由、内容加载（Markdown/MDX 原文）、环境变量与构建性能在生产环境的稳定性。

## 项目结构与关键点
- 入口链路：index.html → src/main.jsx → App.jsx（BrowserRouter）  #  
- 内容加载：utils/contentLoader.js 使用 import.meta.glob('../content/**/*.{md,mdx}', { as: 'raw' })  #  
- 构建配置：vite.config.js 启用 @vitejs/plugin-react、tailwindcss/vite，assetsInclude: ['**/*.md']  #  
- 环境变量：api/client.js 读取 import.meta.env.VITE_API_BASE_URL  #  
- 资源与搜索：public 与 src/assets 共存；features/search 使用 minisearch  #  

## 风险与问题
1) MDX 未纳入 assetsInclude，原始加载可能在构建路径解析中不一致  #  
2) BrowserRouter 缺少 SPA 回退，Vercel 上深链接可能 404  #  
3) 大量 md/mdx 原文随仓库增长会增大 bundle 与首屏解析成本  #  
4) 未配置 Vercel 环境变量将导致 API 前缀为空（请求失败）  #  

## 部署到 Vercel 建议
- vercel.json（放根目录）  #  
  ```
  {
    "rewrites": [{ "source": "/((?!api).*)", "destination": "/index.html" }],
    "buildCommand": "npm run build",
    "outputDirectory": "dist"
  }
  ```
  说明：对所有非 /api 路径进行 SPA 回退，确保客户端路由正常。  #  

- vite.config.js（不在本报告中修改，仅建议）  #  
  - 调整 assetsInclude 为 ['**/*.md', '**/*.mdx'] 保证 mdx 原始加载一致  #  
  - 保持 @vitejs/plugin-react 与 tailwindcss/vite 插件顺序稳定  #  

- 环境变量（Vercel Dashboard → Settings → Environment Variables）  #  
  - VITE_API_BASE_URL（Preview 与 Production 分别配置）  #  
  - 如使用外部 API，注意跨域策略与鉴权；可选使用 Edge Functions 代理  #  

## 性能与体积优化
- 按需/分片加载内容与索引：路由进入分类后再加载对应 md/mdx 与子索引  #  
- 预生成或按需加载搜索索引：减少客户端索引构建时间  #  
- 缓存策略：为 immutable 静态资源设置长缓存（Cache-Control: public, max-age=31536000, immutable）  #  
- 图片继续使用 vite-plugin-image-optimizer，确保 public 与 src/assets 引用一致  #  

## SEO 与可观测性（可选）
- 增加 sitemap.xml 与 robots.txt（public 下）  #  
- 保留 index.html 中的 meta，并考虑 Open Graph/Twitter Card  #  
- 部署后使用 Vercel Analytics 与 Web Vitals 监控性能  #  

## 验收清单
- [ ] vercel.json 生效，深链接可直接访问不 404  #  
- [ ] Vercel 环境变量已设置，并在客户端确认 apiClient 请求前缀  #  
- [ ] 构建产物 dist 体积与首屏性能在可接受范围  #  
- [ ] 内容加载 md+mdx 无 404/解析异常  #  

## 结论
该项目结构清晰，静态部署到 Vercel 可行。需要补齐 mdx 资产包含与 SPA 回退，并对内容规模做按需与分片加载以控制体积与性能。完成上述建议后，可稳定上线。
