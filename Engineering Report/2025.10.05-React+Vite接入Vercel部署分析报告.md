# React+Vite 接入 Vercel（GitHub）部署分析报告
- 作者：CodeBuddy 和 刘宇航
- 日期：2025-10-05

## 背景
项目为 React+Vite 的单页应用（SPA），内容以 Markdown/MDX 文件为主，通过 ReactMarkdown 渲染。目标是连接 GitHub，以 Vercel 自动化部署并上线生产环境。

## 分析过程
- 结构盘点：Vite 构建、React 路由、content 原文加载、SEO 资源与 vercel.json。
- 渲染链路：import.meta.glob 读取原文，ReactMarkdown + remark/rehype 插件渲染，KaTeX 数学支持。
- 部署要点：Vercel SPA 重写、构建产物目录、缓存策略、域名与 DNS。
- 安全与性能：rehype-raw 的安全边界、首屏体积与代码分割、图片优化。
- SEO 与深链接：sitemap.xml、robots.txt、404 路由回退。

## 主要发现
1. SPA 部署：需确保 vercel.json 重写到 /index.html 且 outputDirectory=dist，适配 BrowserRouter 深链接。
2. Markdown 内嵌 HTML：已启用 rehype-raw，表格等 HTML 现可渲染；如内容来源不完全可信，建议加入 rehype-sanitize 并白名单 table/thead/tbody/tr/th/td 等。
3. 构建与分片：建议使用 manualChunks 拆分 vendor/markdown 依赖，配合路由级懒加载降低首屏。
4. 缓存策略：assets 长缓存、HTML no-cache 已合理；图片建议采用 WebP/AVIF 并限制最大宽度。
5. SEO：sitemap.xml 与 robots.txt 存在并可用；域名变更后需同步更新并在 Search Console 提交。
6. DNS/域名：A 记录 apex→76.76.21.21、CNAME www→cname.vercel-dns.com；或切换 Vercel NS 管理。
7. 环境变量：若暂无后端可不配置；后续需以 VITE_ 前缀在 Vercel 管理（Development/Preview/Production 分环境）。
8. 404 体验：建议提供自定义 404 页面提升用户体验。

## 建议与后续行动
- 必做
  - 保持 vercel.json 的 SPA 重写与缓存策略；构建目录为 dist。
  - 已启用 rehype-raw：在生产验证含表格的页面正确渲染。
  - 为自定义域完成 DNS：apex A、www CNAME；Vercel 绑定域名并强制 HTTPS。
  - 更新 sitemap/robots 至最终域名并在 Search Console 提交。
- 可选优化
  - 引入 rehype-sanitize（白名单表格相关标签）以提升安全性。
  - manualChunks 与路由懒加载控制首屏体积；进一步按需加载 Markdown 渲染插件。
  - 图片资源转换为 WebP/AVIF，静态图片设置尺寸与懒加载。
  - 添加自定义 404 页面。
- 验收步骤
  - 本地：npm run build && npm run preview 验证表格页面渲染。
  - 生产：推送到 GitHub 触发 Vercel 部署后，访问生产 URL 检查表格与深链接。
  - SEO：Search Console 验证与提交。

## 结论
项目已具备在 Vercel（连接 GitHub）稳定部署的条件；rehype-raw 解决了 Markdown 内嵌 HTML 表格渲染问题。建议在生产中按需引入 sanitize、优化首屏与图片资源，并完善域名与 SEO 配置，以获得更好的性能与搜索可见性。
